# Lantern Ledger

Decisions delegated by the user; no interactive interview occurred. Six original puzzles form a compact journey through a fictional lantern maker's ledger. Warm paper, forest ink, coral and gold; original CSS line art. Lightweight TypeScript DOM application, no runtime framework or remote assets.

Every N×N board contains 1…N once in each row and column. Colored connected cages partition the board. Supported rules: fixed value, sum, product, two-cell absolute difference, two-cell exact larger/smaller quotient, odd, even, unordered consecutive distinct values (straight), and a two-cell comparison in labelled reading order. Repeats in a cage are legal unless they share a row/column or a straight forbids them. Tutorial and selected-cage explanations define these semantics explicitly. Subtraction and division intentionally use only two cells, avoiding unverified multi-cell semantics.

Progression: 4×4 addition, 4×4 products, 4×4 arithmetic, 5×5 parity, 5×5 straights, 5×5 comparison finale. All puzzles accessible for replay, completion badges and a next-puzzle action guide progression. No timers or penalties. Enter values, toggle candidate notes, erase, undo/redo, explain a hint, inspect legal cage combinations, request contradiction checking, reset with cancel. Hints first use local cage/row/column deductions; fallback tests every candidate for existence of a valid completion and explicitly names exhaustive reasoning. Never use a stored solution as a deduction. Notes never constrain logical hints or solution validity.

Save values, notes, histories and completion badges per puzzle with a versioned, validated localStorage envelope; invalid or missing fields recover safely. Failed storage is visibly reported. A reset is undoable and preserves earned badges. Repeated value inputs are no-ops, repeated note inputs toggle. Completion depends on constraint satisfaction. Keyboard arrows navigate, 1…N enter, N toggles notes, Delete clears, Ctrl/Cmd+Z undo, Shift+Ctrl/Cmd+Z redo. Buttons and cells labelled, focus visible, live feedback; narrow layouts work without horizontal overflow.

Authorized test seams: rule predicates, solver/uniqueness, history/notes transitions, save validation, visible browser controls. Independent Python verifier uses a separate row-permutation search and independent rule predicates. Browser evidence must distinguish visible Chrome play from automated numerical checks.
